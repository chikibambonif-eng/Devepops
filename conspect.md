# 🐧 DevOps База: Git и Дикие земли Linux

## 🛠️ Секция 1: Markdown и Базовый Git

### 1.1 Разметка Markdown (Шпаргалка)
* `# Заголовок` — главный заголовок (чем больше `#`, тем меньше размер).
* `* Текст*` или `**Текст**` — выделение курсивом или жирным шрифтом.
* Блок кода выделяется тремя обратными апострофами \`\`\` (клавиша "Ё" на клавиатуре).

### 1.2 Машина времени Git
* `git init` — создать пустой локальный репозиторий в текущей папке.
* `git add .` — подготовить **все** измененные файлы к сохранению (точка обязательна!).
* `git commit -m "название"` — сделать снимок (сохранение) изменений.
* `git config --global user.name "Имя"` — настроить имя автора коммитов.
* `git config --global user.email "Почта"` — настроить почту автора коммитов.

### 1.3 Связка с GitHub через SSH
* `ssh-keygen -t ed25519 -C "почта"` — сгенерировать безопасный SSH-ключ (на вопросы о пароле жать *Enter*).
* `cat ~/.ssh/id_ed25519.pub` — вывести публичный ключ, чтобы скопировать его целиком в настройки GitHub.
* `git remote add origin git@github.com:ЮЗЕР/РЕПО.git` — привязать удаленный репозиторий по SSH.
* `git branch -M main` — переименовать главную ветку в стандарт `main`.
* `git push -u origin main` — отправить локальный код в облако GitHub.

## 📊 Секция 2: Процессы и Системные Службы

### 2.1 Навигация и Файлы
* `pwd` — показать точный путь до папки, где ты сейчас стоишь.
* `ls -la` — показать список всех файлов в папке, включая скрытые (например, папку `.git`).
* `cd название_папки` — зайти внутрь папки (**нельзя** использовать `cd` для открытия текстовых файлов!).
* `nano имя_файла` — открыть файл в текстовом редакторе.

### 2.2 Укрощение процессов (ps aux и top)
* `ps aux` — **мгновенный снимок** всех запущенных программ на сервере.
* `top` — **видеокамера**, показывающая нагрузку и процессы в реальном времени (выход на клавишу `q`).
* **Разбор колонок:**
  * `PID` — цифровой паспортный номер программы в системе.
  * `USER` — кто запустил (твоя учетка или администратор `root`).
  * `COMMAND` — имя запущенной программы (например, `ping` или `nginx`).
* `ps aux | grep имя` — отфильтровать список процессов и найти конкретную программу.

### 2.3 Уничтожение процессов и Сигналы `kill`
* `kill -15 [PID]` (`SIGTERM`) — вежливая просьба к программе завершить работу и сохранить данные.
* `kill -9 [PID]` (`SIGKILL`) — **ядерный удар**, мгновенное принудительное уничтожение зависшего процесса на уровне ядра.

### 2.4 Анатомия Собеса: Зомби и Сироты
* **PID 1 (`systemd` / `/sbin/init`)** — самый первый процесс в Linux. Главный босс, родитель всех процессов.
* **Процесс-сирота (Orphan):** У него умер родитель, пока он работал. Его мгновенно усыновляет **PID 1**. Это нормальные рабочие процессы.
* **Процесс-зомби (Zombie):** Процесс уже умер, но его родитель завис и не прочитал отчет о смерти. Зомби висит мертвым грузом в таблице PID. `kill -9 [PID_ЗОМБИ]` не сработает, потому что он уже мертв. 
* **Как лечить зомби:** Либо убить живого родителя зомби через `kill -9`, либо пнуть родителя сигналом `kill -17` (`SIGCHLD`), чтобы он проверил список процессов.

### 2.5 Управление службами через Systemd
Фоновые службы (демоны), которые работают без окон (Docker, Nginx), описываются в файлах `.service` и управляются утилитой `systemctl`.
* `sudo systemctl start [служба]` — запустить службу прямо сейчас.
* `sudo systemctl enable [служба]` — добавить службу в автозагрузку при включении ПК.
* `sudo systemctl enable --now [служба]` — **лайфхак профи:** и запустить сейчас, и добавить в автозагрузку одной командой.

## 🌐 Секция 3: Сети, Метрики и Nginx

### 3.1 Метрики нагрузки (Quest 3.1)
* `wa` (CPU Wait) — процессор простаивает и ждет, пока медленный жесткий диск прочитает/запишет файлы.
* `Load Average` (LA) — средняя нагрузка за последние 1, 5 и 15 минут. 
  * *Пример:* На 1-ядерном процессоре LA `3.0` означает, что сервер **дико перегружен** (в очереди стоят еще 2 процесса). На 4-ядерном процессоре LA `3.0` — это нормальная рабочая нагрузка.

### 3.2 Дисковое пространство (Quest 3.2)
* `df -h` — показать общую занятость всех дисков в человекочитаемом виде (в ГБ и МБ).
* `du -sh /путь/к/папке` — показать точный вес конкретной папки или лог-файла.

### 3.3 Сетевой Траблшутинг (Quest 3.3)
* `sudo ss -tlnp` — показать список всех TCP-портов (`-t`), которые сейчас слушают (`-l`) входящие соединения в виде номеров (`-n`) с именами и PID программ (`-p`), которые их заняли.
* **Listening (Слушающий порт)** — состояние программы, когда она не отправляет данные сама, а сидит и **ждет** запроса/подключения с внешней стороны.

### 3.4 Веб-сервер Nginx (Quest 3.4)
* **Reverse Proxy (Обратный прокси):** Nginx ставится на «входные ворота» сервера (порт 80) как жесткий администратор. Он принимает весь трафик из интернета и безопасно перекидывает его на внутренний порт (например, 8080), где сидит твое Python/Go приложение.
* **Правила обновления конфига:**
  * `sudo systemctl reload nginx` — перезагрузить настройки **на лету (Zero Downtime)**. Старые пользователи не вылетают с ошибками, новые процессы подхватывают новые настройки. Идеально для живого продакшена.
  * `sudo systemctl restart nginx` — жестко выключить и включить сервер. Вызывает короткий сбой сайта и обрывает текущие сессии пользователей (плохой вариант для рабочих систем).
